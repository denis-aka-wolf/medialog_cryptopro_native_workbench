# Medialog CryptoPro Native Workbench

Тестовый Flutter Windows Desktop стенд для проверки внешнего CryptoPro Bridge.

## Что умеет приложение

- Проверяет запуск Bridge и его `status`.
- Получает список сертификатов.
- Позволяет выбрать сертификат по thumbprint.
- Создаёт detached-подпись.
- Создаёт attached-подпись.
- Проверяет detached-подпись.
- Показывает ответы, ошибки и технический журнал.

Это именно тестовый стенд, а не пользовательский интерфейс Medialog Sign.

## Важно о native Bridge

В этой поставке находится Dart/Flutter тестер и контракт JSON. Нативный C++ Bridge пока не объявлен готовым: для корректной реализации CAdES нужно извлечь и изучить содержимое `SDK CSP/cadessdk.msi`, включая заголовки, библиотеки, документацию и примеры. В предоставленном `sdk.zip` подтверждены примеры CryptoAPI/CryptMsg, но пример `CryptMsgSign` сам по себе формирует CMS/PKCS#7 и не доказывает реализацию требуемого профиля CAdES.

Не подменяйте CAdES обычным CMS и не используйте такой результат в документообороте без проверки требований принимающей системы.

## Запуск

1. Установите Flutter SDK и настройте Windows Desktop.
2. Откройте каталог `app`.
3. Выполните:

```powershell
flutter create --platforms=windows .
flutter pub get
flutter run -d windows
```

4. В поле Bridge EXE укажите полный путь к собранному нативному Bridge.
5. Нажмите «Проверить Bridge», затем «Список сертификатов».
6. Выберите сертификат и проверьте операции на тестовом файле.

Если приложение запускается на Windows Server, запускайте его в том же пользовательском контексте, в котором доступны сертификат и закрытый ключ. Работа в фоне без интерактивной сессии требует отдельной архитектуры и тестирования.
